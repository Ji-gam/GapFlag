# STEP 4-1 — MVP 정의 · Mini PRD

작성일 2026-08-29 · STEP 1(시장검증)~STEP 3(사업계획서 초안) 결과를 바탕으로, 핵심 사업가설을 검증하기 위한 최소 MVP를 정의

---

## 정리: MVP 정의를 위한 사전 확인

### 1. 핵심 사업가설 (STEP 3에서 확정)

동물약 개발기업 R&D팀은 이 문제(위험·기회 데이터 분산)에 실제로 비용을 지불할 의사가 있다.

### 2. 이번 MVP에서 검증할 핵심가설 1개

핵심 사업가설(지불 의사)을 소프트웨어 MVP 하나로 직접 검증하기는 어렵다 — 지불 의사는 실제 결제·계약 상황에서만 확인 가능하기 때문이다. 따라서 사업가설 자체는 바꾸지 않고, 그 전 단계에 있는 하위가설 1개를 이번 MVP에서 검증한다.

> **이번 MVP 검증가설**: "동물약 개발기업 R&D팀 연구원은 성분 단위로 위험×기회를 한 화면에서 비교하고 근거를 확인하면, 기존 방식(개별 DB 수작업 대조)보다 유용하다고 느끼고 다시 사용하고 싶어할 것이다."

이 검증가설은 STEP 2에서 확정한 고객가설("성분 단위로 위험과 기회를 한 화면에서 비교하는 도구를 필요로 할 것이다")과 동일한 것이며, 새로 만든 가설이 아니다. 지불의향은 이 MVP 테스트에서 추가로 관찰하되, 성공 기준의 필수 조건으로는 두지 않는다(별도 검증 필요 항목으로 유지).

### 3. 핵심 사용자 1명

동물약 개발기업 R&D팀에서 신약 후보 성분을 초기 스크리닝하는 연구원

### 4. 사용자가 MVP를 사용하는 구체적인 상황

후보 성분 리스트 중 하나를 놓고, "이 성분이 개·고양이에서 위험한지"와 "아직 아무도 안 건드린 공백(기회)인지"를 판단해야 하는 초기 검토 시점

### 5. 반드시 필요한 핵심기능 3개

| 기능 | 검증에 필요한 이유 |
|---|---|
| 성분명 검색·조회 | 조인 키가 성분명이라는 확정 설계를 사용자가 실제로 쓸 수 있어야 검증가설을 테스트할 수 있음 |
| 2×2 위험×기회 매트릭스 (S1) | "한 화면에서 비교"라는 검증가설의 핵심 — 이 화면 없이는 가설 자체를 테스트할 수 없음 |
| 성분 상세 + 근거 카드 (S2) | "근거를 확인하면"이라는 검증가설의 조건 — 매트릭스만 있고 근거가 없으면 신뢰도를 테스트할 수 없음 |

### 6. 있으면 좋지만 이번 MVP에서는 제외할 기능

- S3 후보 비교 화면 (STEP 3에서 잘라내는 순서 1순위로 이미 확정)
- 실시간 API 조회 (화면은 DB만 읽는다는 원칙에 따라 배치 수집만 사용)
- EPO 특허 밀집도(R4) — 계정·키 발급 의존성 때문에 최소 유지 대상에서 제외
- Green Book 기반 R3·O3 — 공식 API 없음, 파싱 필요해 최소 유지 대상에서 제외
- 성분 동의어 사전 자동화, 다국어, 사용자 계정/로그인 등 — 지금까지 대화에서 확정된 바 없음, 이번 MVP 범위 아님

### 7. 입력 데이터

- 사용자 입력: 성분명(자유 텍스트 또는 사전 등록된 목록에서 선택), 종(개/고양이)
- 시스템 보유 데이터: openFDA ADAE(R2), Open Targets(R1), Europe PMC(O1) — STEP 3에서 "최소 유지 대상"으로 확정된 3개 소스. 배치 스크립트(`scripts/build_cache.py`)로 사전 수집해 DB에 저장

### 8. 처리 과정

성분명 정규화(동의어 사전 대조) → DB에서 해당 성분·종의 R1/R2/O1 원자료 조회 → 확정된 산식(§4-2)으로 지수 환산 → 값이 없는 구성요소는 0이 아닌 NULL로 유지하고 커버리지 계산 → 위험지수·기회지수·사분면 위치 산출

### 9. 사용자에게 보여줄 핵심 결과

- 성분이 위치한 사분면(비어 있는 이유가 있음 / 우선 검토 / 회피 / 경쟁 구간)
- 위험지수·기회지수 값과 커버리지 %
- 근거 카드: 각 구성요소별 원본 출처 링크 및 요약
- 데이터 없음(NULL) 항목은 회색 표시 + "위험이 없다는 뜻이 아닙니다" 문구
- 화면 하단 "본 도구는 참고용이며 의료·규제 판단을 대신하지 않습니다" 고지

### 10. 성공 여부를 판단할 기준

- 기능의 정상 작동 여부가 아니라, 실제 R&D 연구원(또는 유사 배경을 가진 테스트 참여자)이 결과 화면을 보고 "이게 왜 유용한지" 스스로 설명할 수 있는가
- 매트릭스와 근거 카드를 본 뒤 "기존에 하던 방식보다 빠르다/편하다"고 말하는가
- "다음에도 다른 성분으로 또 써보고 싶다"는 반응이 나오는가
- 구체적인 목표 수치(예: NPS 점수, 응답률)는 [추가 검증 필요] — 지금까지 대화에서 근거 있는 수치가 확정된 바 없으므로 임의로 만들지 않음. 실제 사용자 테스트에서 관찰해 사후에 채워야 할 항목

# Mini PRD

## 1. 프로젝트명

Gap & Flag MVP — 성분 위험×기회 스크리닝

## 2. 서비스 목적

동물약 개발기업 R&D팀 연구원이 성분 단위로 위험(레드플래그)과 기회(연구 공백)를 한 화면에서 교차 확인하도록 해, "성분 단위 비교가 기존 수작업보다 유용한가"라는 하위가설을 검증한다.

## 3. 핵심 사용자

동물약 개발기업 R&D팀에서 신약 후보 성분을 초기 스크리닝하는 연구원 1명(대표 페르소나)

## 4. 핵심 사업가설

동물약 개발기업 R&D팀은 이 문제(위험·기회 데이터 분산)에 실제로 비용을 지불할 의사가 있다.

## 5. 이번 MVP에서 검증할 가설

동물약 개발기업 R&D팀 연구원은 성분 단위로 위험×기회를 한 화면에서 비교하고 근거를 확인하면, 기존 방식(개별 DB 수작업 대조)보다 유용하다고 느끼고 다시 사용하고 싶어할 것이다.

## 6. User Flow

입력(성분명·종 선택) → 처리(DB 조회 + 지수 계산) → 결과(2×2 매트릭스 위치 + 근거 카드)

## 7. 핵심 기능

1. 성분명 검색·조회 — 사전 등록된 성분 목록에서 검색하거나 직접 입력
2. 2×2 위험×기회 매트릭스 표시 (인라인 SVG)
3. 성분 상세 + 근거 카드 (구성요소별 출처 링크, NULL 항목 회색 표시)

## 8. 사용할 데이터

- 사용자 입력 데이터: 성분명, 종(개/고양이)
- 서비스가 처리할 데이터: openFDA ADAE(R2), Open Targets(R1), Europe PMC(O1) 배치 수집 결과, 원본 API 응답(raw JSON) 포함
- 아직 확보되지 않았거나 검증이 필요한 데이터: [추가 검증 필요] EPO 특허(R4), Green Book(R3·O3) — API 키 발급·파싱 미완료 / [추가 검증 필요] 대상 성분 30~50건 최종 목록 확정 여부

## 9. 주요 화면

1. 성분 검색 화면
2. 2×2 매트릭스 화면 (S1)
3. 성분 상세·근거 카드 화면 (S2)

## 10. 결과 화면에 반드시 표시할 정보

사분면 위치, 위험지수·기회지수 값, 구성요소별 커버리지 %, 근거 카드(출처 링크 포함), NULL 항목 회색 표시 + "위험이 없다는 뜻이 아닙니다" 문구, 하단 면책 문구("참고용이며 의료·규제 판단을 대신하지 않습니다")

## 11. MVP 성공 기준

- 핵심가치 이해: 사용자가 매트릭스를 보고 별도 설명 없이 "위험은 낮은데 아직 공백이 크다" 같은 해석을 스스로 말할 수 있는가
- 문제 해결 정도: 기존에 여러 DB를 수작업으로 대조하던 것과 비교해 "더 빠르다/명확하다"고 느끼는가
- 재사용 의향: 다른 성분으로도 다시 써보고 싶다고 말하는가
- 지불의향: 이 도구에 팀 예산으로 비용을 지불할 의향이 있는지 물어보고 반응을 기록 (핵심 사업가설과 직결되므로 반드시 관찰하되, 이번 MVP의 통과/실패 기준으로 강제하지는 않음)
- 구체적 수치 기준은 [추가 검증 필요] — 실제 사용자 테스트에서 관찰해 채울 항목

## 12. 이번 MVP에서 구현하지 않을 기능

S3 후보 비교, 실시간 API 조회, EPO 특허(R4) 구성요소, Green Book 기반 R3·O3, 사용자 계정/로그인, 성분 동의어 사전 자동화, 다국어 지원

## MVP 핵심 요구사항 요약

1. 목적: 성분 단위 위험×기회 매트릭스가 기존 수작업 대조보다 유용한지 검증
2. 사용자: 동물약 개발기업 R&D팀 초기 스크리닝 연구원 1명(페르소나)
3. 검증가설: 성분 단위 위험×기회 교차 비교가 유용하며 재사용 의향을 만든다
4. 핵심 기능 3개: 성분 검색, 2×2 매트릭스(S1), 상세+근거 카드(S2)
5. 데이터: openFDA(R2)·Open Targets(R1)·Europe PMC(O1) 배치 수집, 원본 JSON 보관
6. 원칙: 데이터 없음=NULL(0 아님), 커버리지 % 병기, 화면은 DB만 읽음
7. 화면 3개로 제한: 검색 → 매트릭스 → 상세/근거
8. 제외: S3 비교, 실시간 조회, EPO 특허, Green Book, 로그인
9. 성공 기준: 사용자가 매트릭스를 스스로 해석하고 재사용 의향을 보이는가(수치는 테스트 후 확정)
10. 지불의향은 관찰만 하고 이번 MVP 통과 기준에는 포함하지 않음(핵심 사업가설은 별도로 추적)
